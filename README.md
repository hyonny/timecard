# Timecard

freee人事労務の出勤を打刻する、macOS用の小さな常駐アプリです。出勤ボタンが1個だけのパネルを、デスクトップの好きな場所に置いて使います。

個人で作った非公式のツールで、freee株式会社とは関係がありません。

## 作った理由

freee人事労務で「退勤を自動打刻する」設定を使うと、出勤から24時間後に退勤が自動で記録されます。ところが、前日より早い時刻に出勤すると前日の退勤がまだ記録されておらず、出勤の前に退勤の打刻を求められます。そこで退勤を押すと、押した時刻が前日の退勤時刻になります。毎回ブラウザで勤怠を修正する手間がかかっていました。

このアプリは、出勤ボタンを押したときに前日の退勤が未記録なら、前日の退勤時刻を「出勤の9時間後」に書き込んでから当日の出勤を打刻します。9時間は勤務8時間と休憩1時間の合計です。

## 動作

ボタンを押すと、アプリは直近3日分の打刻と前日の勤怠をfreeeから取得し、次の順に判定します。

1. いまの勤務日にすでに出勤打刻があれば、何も書き込みません。
2. 前回の出勤に対する退勤が記録済みなら、出勤だけを打刻します。
3. 前回の退勤が未記録なら、前回の勤怠を「出勤時刻から9時間後に退勤」に更新してから、出勤を打刻します。

勤務日の境目は朝5時です。5時より前は前日の勤務日として扱います。

前回の出勤から9時間たっていない場合は、退勤を書き込まずにメッセージを表示します。退勤の記録に失敗した場合は、出勤を打刻せずにエラーを表示します。

### 操作

| 操作 | 動作 |
|---|---|
| クリック | 出勤を打刻します。出勤済みのときは出勤時刻を表示します |
| ドラッグ | パネルを移動します。位置は次回の起動時にも保たれます |
| 右クリック | 状態の再取得、freee連携の設定、ログイン時に起動、終了を選べます |

パネルは全デスクトップで常に手前に表示されます。フルスクリーンのアプリの上には表示されません。

## 必要なもの

- macOS 14以降
- Xcode、またはSwift 6のツールチェーン
- freee人事労務のアカウント（打刻と勤怠のAPIを使えるプラン）
- freeeアプリストアの開発者ページで作成したアプリ

## インストール

```sh
git clone https://github.com/hyonny/timecard.git
cd timecard
./scripts/bundle.sh --install
```

スクリプトはリリースビルドを作り、`/Applications/Timecard.app`に入れて起動します。`--install`を付けなければ、`build/Timecard.app`を作るだけです。

署名には、キーチェーンにあるApple Developmentの証明書を使います。証明書が無ければad-hoc署名になります。ad-hoc署名ではビルドのたびにmacOSが別のアプリとして扱うため、キーチェーンへのアクセス許可を毎回求められます。

## freeeとの連携

初回の起動時は、パネルに「設定」と表示されます。クリックすると設定画面が開きます。

1. [freeeの開発者ページ](https://app.secure.freee.co.jp/developers/applications)でアプリを作成します。
2. コールバックURLに`urn:ietf:wg:oauth:2.0:oob`を設定します。
3. 権限で、人事労務の打刻、勤怠、ユーザー情報の参照と更新を有効にします。
4. 設定画面にClient IDとClient Secretを入力し、「認可ページを開く」を押します。
5. ブラウザに表示された認可コードを設定画面に貼り付けて、「連携する」を押します。

連携に成功すると、パネルが「出勤」ボタンに変わります。Client Secretとトークンは、macOSのキーチェーンに保存されます。

## 制限と確認の状況

freeeの打刻APIで打刻時刻を指定できるのは、管理者権限のユーザーだけです。このアプリは一般権限でも使えるように、前日の退勤を勤怠の更新API（`PUT /api/v1/employees/{employee_id}/work_records/{date}`）で書き込みます。会社の設定で従業員による勤怠の編集が禁止されている場合は、退勤を記録できません。

勤怠を更新しても出勤打刻が拒否された場合に備えて、予備の手順も実装しています。予備の手順では、その時刻で退勤を打刻し、退勤時刻を9時間後に書き直してから、出勤を打刻します。

freeeとの連携と打刻の取得は、実際のアカウントで確認しました。退勤を補完する処理は単体テストで確認しただけで、実際のアカウントではまだ動かしていません。休憩は会社の自動記録の設定に任せており、アプリは休憩を書き込みません。

次の機能はありません。

- 退勤と休憩の打刻
- 複数の事業所の切り替え
- 9時間という長さや、朝5時という境目の設定画面（変更するにはソースコードを書き換えます）

## 開発

```sh
swift test    # 単体テストを実行
swift build   # デバッグビルド
```

| ディレクトリ | 内容 |
|---|---|
| `Sources/TimecardCore` | 出勤時の判定、freee APIの呼び出し、OAuth、キーチェーンへの保存 |
| `Sources/Timecard` | 常駐パネル、メッセージ表示、設定画面 |
| `Tests/TimecardCoreTests` | 判定とAPI呼び出しの単体テスト |
| `scripts/bundle.sh` | `.app`の組み立てと署名、インストール |

打刻の結果とエラーは`~/Library/Logs/Timecard.log`に記録されます。
